# Атлас казахской истории

Интерактивная веб-карта по истории Казахстана: территории ханств и государств,
сражения и ключевые события, привязанные к временной шкале. Учебный командный проект.

## Быстрый запуск

Понадобится Node.js версии 18 или новее.

```bash
npm install
npm run dev
```

Откройте адрес, который выведет Vite в терминале (обычно `http://localhost:5173`).

Для сборки готового к публикации сайта:

```bash
npm run build
npm run preview
```

> Карта использует тайлы OpenStreetMap/CARTO по сети — для отображения базовой карты
> нужен доступ в интернет. Сами данные о территориях и событиях — локальные и работают offline.

## Архитектура проекта

```
src/
  types/            — TypeScript-типы данных (события, территории)
  data/              — mock-данные: battles/events, территории, "закладки" на шкале времени
    events.ts
    territories.ts
    periods.ts
  hooks/
    useHistoricalData.ts   — центральный стейт: год, фильтры, поиск, вычисляемые списки
  components/
    Layout/Header.tsx      — шапка, поиск, переключение вкладок (карта / список / о проекте)
    Map/                   — карта на Leaflet
      HistoricalMap.tsx
      TerritoryLayer.tsx   — полигоны территорий с тултипами
      BattleMarkers.tsx    — маркеры событий с кластеризацией
    Timeline/Timeline.tsx  — временная шкала, слайдер, "закладки", автопроигрывание
    EventCard/EventCard.tsx — подробная карточка события/битвы
    Filters/FilterPanel.tsx — фильтры по типу события и по государству
    Legend/Legend.tsx       — легенда территорий, видимых в текущем году
    BattlesList/            — страница со списком всех событий
    AboutPanel/              — страница "О проекте"
public/
  geojson/           — папка для более точных GeoJSON-файлов территорий (пока пусто)
```

Данные и отображение разделены: все факты лежат в `src/data`, компоненты только
читают их через хук `useHistoricalData`. Это позволяет команде дополнять/уточнять
исторические данные, не трогая код интерфейса.

## Как это работает

1. `useHistoricalData` хранит выбранный год (синхронизирован с `?year=` в URL),
   фильтры по типу события и по государству, а также поисковый запрос.
2. Территории (`territories.ts`) имеют `startYear` / `endYear` — при смене года
   на карте автоматически остаются только те, что активны в этот момент.
3. События (`events.ts`) показываются, если их год попадает в окно ±12 лет от
   выбранного года (см. константу `EVENT_WINDOW` в хуке) — либо все сразу, если
   включён переключатель "Показать все события" или используется поиск.
4. Клик по маркеру открывает `EventCard` с полной информацией о событии.

## О точности исторических данных — ВАЖНО

- **Границы территорий** (`territories.ts`, поле `geojson`) — упрощённая
  приблизительная реконструкция, нарисованная от руки по общим представлениям
  о регионах (Жетысу, Приаралье, междуречье Волги и Урала и т.д.), а НЕ точные
  оцифрованные исторические карты. Каждая территория помечена
  `isReconstruction: true`, а в интерфейсе об этом дополнительно написано в
  тултипе и в легенде.
- **Координаты сражений** в большинстве случаев помечены `isLocationApproximate: true` —
  точные места многих битв являются предметом дискуссий в источниках.
- **События с пометкой `needsVerification: true`** (например, Орбулакская и
  Аңырақайская битвы, восстание Кенесары) требуют, чтобы команда сверила даты,
  численность войск и детали хода сражений по академическим источникам перед
  защитой проекта — в данных сознательно избегались "красивые", но непроверенные
  цифры (например, соотношение сил в битвах).
- Ни одна дата, координата или факт не выдуманы специально для проекта — но
  рекомендуется дополнительная сверка, особенно там, где стоит пометка о
  приблизительности.

## Как добавить более точные исторические границы

См. `public/geojson/README.md` — коротко: подготовьте `.geojson`-файл территории
и замените содержимое поля `geojson` соответствующей записи в `src/data/territories.ts`.
